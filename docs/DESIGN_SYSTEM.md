# Интерфейс каталога

Решение от 4 ноября 2026: React + Radix Themes. Это оформление оболочки каталога, не обязательный стиль ассетов. Ни токены оболочки, ни выбранная тема не попадают внутрь превью паков.

## Почему Radix Themes

Нужна готовая связанная система контролов для поиска, фильтров, вкладок и просмотра кода. Headless-компоненты решают поведение, но оставляют всю визуальную систему на проекте. Radix Themes дает оба слоя без отдельного CSS-фреймворка.

| Кандидат | Что это и лицензия | Решение для этого проекта |
| --- | --- | --- |
| [Radix Themes](https://www.radix-ui.com/themes/docs/overview/getting-started) | Готовая styled React-библиотека; [MIT](https://github.com/radix-ui/themes/blob/main/LICENSE) | Выбрана: общие темы, размеры и состояния; собственный CSS отвечает за сетку каталога |
| [shadcn/ui](https://ui.shadcn.com/docs) | Распространяемые исходники компонентов, не обычный неизменяемый npm UI-kit; [MIT](https://github.com/shadcn-ui/ui/blob/main/LICENSE.md) | Подходит для собственного registry, но здесь потребовал бы поддерживать больше скопированного кода |
| [Base UI](https://base-ui.com/react/overview/about) | Headless React-примитивы без оформления; [MIT](https://base-ui.com/) | Хорошая база поведения, но не готовое визуальное решение |
| [React Aria Components](https://react-aria.adobe.com/) | Неоформленные доступные компоненты; [Apache-2.0](https://github.com/adobe/react-spectrum/blob/main/LICENSE) | Уместны для более сложного менеджера с коллекциями и выделением; для текущего каталога больше сборки вручную |
| [Geist Design System](https://vercel.com/geist/introduction) | Внутренняя система Vercel с публичным справочником; не открытая библиотека для установки | Только ориентир по плотности и типографике. Компоненты и иконки не копируем: [разъяснение Vercel](https://community.vercel.com/t/geist-icons-lack-clear-installation-import-and-usage-documentation/34481) |

Лицензии каждого пакета и шрифта проверяются отдельно. Например, открытая лицензия шрифтов Geist не распространяется на компоненты Geist. В этом интерфейсе используется локальный Inter, не Geist.

## Реальная настройка

Источник: `frontend/app.jsx`, `frontend/styles.css`, корневой `package-lock.json`. Зафиксированы React 19.3.1, Radix Themes 3.3.0, Radix Icons 1.3.2, Inter Variable 5.3.0 и esbuild 0.28.2. Обновление зависимостей проводится отдельно от добавления ассетов.

```jsx
<Theme
  appearance={appearance}
  accentColor="gray"
  grayColor="gray"
  radius="medium"
  scaling="100%"
  panelBackground="solid"
  hasBackground={false}
>
  {/* Только оболочка каталога */}
</Theme>
```

`appearance` принимает разрешенную светлую или темную тему. Пользователь выбирает светлую, темную или системную; системный режим реагирует на изменение настройки устройства. Выбор сохраняется в `localStorage`. `site/theme-init.js` устанавливает режим до запуска React.

Токены оболочки имеют префикс `--lib-`. Основные значения:

| Токен | Светлая тема | Темная тема |
| --- | --- | --- |
| `--lib-page` | `#fafafa` | `#111111` |
| `--lib-surface` | `#ffffff` | `#171717` |
| `--lib-subtle` | `#f4f4f4` | `#1e1e1e` |
| `--lib-ink` | `#202020` | `#ededed` |
| `--lib-secondary` | `#626262` | `#a6a6a6` |
| `--lib-muted` | `#717171` | `#969696` |
| `--lib-border` | `#e5e5e5` | `#2c2c2c` |
| `--lib-focus` | `#666666` | `#b5b5b5` |

Основной шрифт: локальный Inter Variable с системным fallback. Код и имена файлов используют системный monospace. База интерфейса 14 px, заголовок страницы 29 px, заголовок карточки 16 px, подписи 11-13 px. Иерархия строится на размере, весе и отступах, а не на дополнительных цветах.

Контент ограничен 1480 px, боковое поле на широком экране 48 px. Плитка имеет три колонки, до 1160 px две, до 680 px одну. Поля уменьшаются до 20 px на мобильном. Карточки имеют превью 16:10 и радиус 8 px; диалог на мобильном занимает экран. Эти значения принадлежат оболочке и не навязываются самим материалам.

## Правила взаимодействия

1. Первый экран для работы: поиск, коллекция, фильтры и реальные превью. Без рекламного hero, градиентов и декоративной статистики.
2. Цвет появляется внутри материалов. Оболочка нейтральная в обеих темах; переключение темы не инвертирует превью.
3. Поиск доступен клавишей `/`, если фокус не находится в поле или диалоге. Категория и тег видны как снимаемые фильтры. Есть отдельные состояния загрузки, ошибки и пустой выдачи.
4. Плитка и список показывают последние версии паков. В диалоге можно выбрать точную версию; ссылка содержит `#pack=<id>@<version>`. Избранное сохраняется локально по id пака.
5. Диалог разделен на «Превью», «Файлы и код», «Правила». Основные действия: скачать пак, прочитать или скопировать код, взять контекст для чата. Большие и нетекстовые файлы предлагаются для скачивания.
6. Radix управляет фокусом и закрытием диалогов. После закрытия пака фокус возвращается к карточке или поиску; кнопки-иконки имеют текстовые названия для скринридера. Видимый focus ring не удаляем.
7. Переходы в собственном CSS занимают 120-160 мс. `prefers-reduced-motion: reduce` отключает анимации и переходы оболочки. Обязательное действие не должно зависеть только от hover.
8. Превью всегда в sandboxed iframe без `allow-same-origin`. JS-пак на карточке не запускается; в подробном просмотре запуск разрешает отдельная кнопка. Каталог отображает код как текст, не вставляет HTML из манифеста.

## Как менять интерфейс

Правки оболочки делаются в `frontend/`. Для кнопок, вкладок, диалогов, выбора и всплывающих панелей сначала используйте имеющиеся компоненты Radix Themes, затем классы раскладки. Не добавляйте второй UI-kit ради одного контрола и не импортируйте CSS из `packs/`.

После изменения: `npm test`, `npm run validate`, `npm run build`, затем браузерная проверка светлой/темной темы, клавиатуры, мобильного экрана, диалога, файлов и изоляции. Сборка с target `safari16` не является доказательством проверки в Safari/WebKit. Порядок публикации и HTTP-защита: [DEPLOYMENT.md](DEPLOYMENT.md).
