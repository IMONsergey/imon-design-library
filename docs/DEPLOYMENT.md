# Публикация

Адрес: https://css.imon.world. Источник: ветка `main` репозитория `IMONsergey/imon-design-library`.

## Как устроено

- DNS обслуживают `ns1.reg.ru` и `ns2.reg.ru`. Поддомен уже разрешается в `94.249.186.240` через существующую общую запись. Остальные записи зоны не менялись.
- Отдельный виртуальный хост nginx обслуживает только `css.imon.world`. HTTP перенаправляется на HTTPS, ACME-проверка остается доступной для продления сертификата.
- React и Radix Themes собираются заранее через esbuild. nginx отдает статический результат: нет базы данных, постоянно работающего Node-приложения, формы загрузки, открытого API записи или платных сервисов.
- Пользователь `imon-design-library` без входа в систему собирает и публикует релизы. Он не использует GitHub-токен: репозиторий публичный.
- Таймер `imon-design-library.timer` проверяет main примерно раз в 2 минуты. Он скачивает изменения, запрещает откат/перезапись истории, проверяет неизменность опубликованных паков, устанавливает доверенные зависимости интерфейса из lockfile, запускает валидацию, тесты и сборку.
- Только успешная сборка попадает в `releases/<commit>`. Символическая ссылка `current` переключается атомарно. `previous` сохраняет прошлый релиз. Неудачная сборка не заменяет текущий сайт.
- HTML каталога отдается с `no-store`, остальные изменяемые ресурсы и исходники с `no-cache`. Только шрифты с хешированными именами имеют длительный immutable-кеш. Версии паков остаются неизменными на уровне Git.

## Сборка интерфейса

На машине сборки нужен Node.js 24 и npm из того же runtime. Корневой `package-lock.json` обязателен; версии прямых зависимостей закреплены без диапазонов. Контроллер выполняет эквивалент:

```sh
npm ci --ignore-scripts --include=dev --include=optional --no-audit --fund=false
npm run validate
npm test
npm run build
```

`--include=dev` нужен для esbuild даже при `NODE_ENV=production`. `--include=optional` сохраняет платформенный бинарник сборщика, `--ignore-scripts` отключает npm lifecycle-скрипты. Это установка только доверенного корня проекта; зависимости или hooks из импортируемых паков не устанавливаются и не выполняются.

`frontend/app.jsx` и `frontend/styles.css` компилируются в `.cache/ui/`. Оттуда проверенная сборка вместе с паками попадает в `dist/`. HTML-оболочка, favicon и ранний выбор темы берутся из `site/`; файлы ассетов не входят в bundle. Шрифты Inter, JS и CSS отдаются с нашего домена. Сборщик добавляет `third-party-notices.txt` с лицензиями включенных библиотек и шрифтов.

### CSP и миграция

Radix использует динамические стили для части интерактивных компонентов. HTML содержит один маркер `__IMON_CSP_NONCE__`; штатный локальный сервер заменяет его случайным значением, nginx использует новый `$request_id` для каждого запроса. То же значение разрешено только в `style-src` и передается через `get-nonce`. Скрипты остаются `script-src 'self'`, без `unsafe-inline`. Inline-атрибуты стилей оболочки отдельно разрешены через `style-src-attr`.

Для двух статических стилей внутренних viewport Radix Select и ScrollArea добавлены точные SHA-256 в `style-src`: Themes 3.3.0 не передает nonce этим вложенным компонентам. `tests/radix-csp.test.mjs` сверяет тексты, хеши, закрепленные версии библиотек и политику nginx. Это не общее разрешение inline-style: при обновлении библиотеки новые тексты требуют отдельной проверки.

Для нового frontend нужно вручную установить проверенные `deploy/update.mjs` и `deploy/nginx.conf`, проверить наличие `http_sub_module` в nginx, затем выполнить `nginx -t` перед reload. Один коммит в main не обновляет root-owned контроллер или nginx. Нельзя публиковать новый HTML через старую конфигурацию с незамененным маркером или фиксированным nonce.

Это исключение относится только к оболочке. `/previews/` сохраняет HTTP sandbox, `connect-src 'none'` и ограничения внешних ресурсов; `/raw/` отдает исходники как вложения с инертным CSP. `allow-same-origin` превью не получает.

## Пути на сервере

| Назначение | Путь |
| --- | --- |
| Только Git-объекты | `/srv/imon-design-library/git` |
| Рабочие каталоги сборок | `/srv/imon-design-library/builds/<commit>` |
| Кеш установщика npm | `/srv/imon-design-library/npm-cache` |
| Публичные релизы | `/srv/imon-design-library/releases/<commit>` |
| Текущий / предыдущий релиз | `/srv/imon-design-library/current`, `/srv/imon-design-library/previous` |
| Контроллер публикации, владелец root | `/usr/local/lib/imon-design-library/` |
| Конфигурация nginx | `/etc/nginx/conf.d/css.imon.world.conf` |
| Общие HTTP-заголовки проекта | `/etc/nginx/snippets/imon-design-security.conf` |
| Сертификат | `/etc/letsencrypt/live/css-imon-world/` |

Контроллер устанавливается отдельно от main и сам не обновляет себя. Изменения `deploy/` нужно проверить и установить вручную; обычный импорт паков этого не требует. Это не дает коммиту заменить привилегированную конфигурацию сервера.

## Проверки

```sh
systemctl status imon-design-library.timer
systemctl status imon-design-library.service
journalctl -u imon-design-library.service -n 80 --no-pager
curl -fsS https://css.imon.world/health.json
curl -fsS https://css.imon.world/api/catalog.json
sudo systemctl start imon-design-library.service
```

У успешного oneshot-сервиса нормальное состояние `inactive (dead)` после завершения; результат должен быть `success` и код завершения 0. Работает именно timer.

Браузерный прогон `tests/browser-smoke.mjs` выполняется отдельно от `npm test` и автоматической серверной публикации. Playwright нужен только на машине проверки, не в зависимостях сайта. `PLAYWRIGHT_MODULE` и `CHROME_BIN` указывают установленные инструменты; `LIBRARY_URL=https://css.imon.world` проверяет опубликованный сайт. Без URL поднимается временный сервер на loopback.

Для дополнительных движков задаются `BROWSER_ENGINE=firefox` с `FIREFOX_BIN` или `BROWSER_ENGINE=webkit` с `WEBKIT_BIN`. Каждый запуск использует новый временный контекст без пользовательского профиля. Проверка содержимого буфера обмена выполняется только в Chromium; это ограничение явно попадает в результат. Linux WebKit не заменяет проверку нативного Safari на устройстве.

На установленном Playwright `1.64.0-alpha-1790635538000` полный WebKit security smoke запускается без `SCREENSHOTS_DIR`. Отдельный диагностический прогон дал 0 CSP-нарушений после загрузки, Select и Dialog, затем ровно одно `style-src-elem` нарушение на каждый `page.screenshot()` (`sourceFile: ""`, строка 5). Причина в screenshotter Playwright: для синхронизации WebKit он без nonce временно вставляет `<style>body {}</style>`. Даже `animations: 'allow', caret: 'initial'` не отключают этот шаг. Поэтому визуальные кадры собираются отдельно от чистого security smoke; ошибки не подавляются, CSP приложения ради снимков не ослабляется.

Перед выпуском проверяются поиск, пустая выдача, избранное, плитка/список, обе темы, файлы и копирование кода, клавиатура, ZIP, изоляция превью и ширины 320/390/768/1440. Папки, коллекции и ассеты должны открываться обычными страницами, а не preview dialog. Проверяются стабильные ссылки `#pack=<id>` и `#pack=<id>&asset=<asset-id>`, перезагрузка и «Назад», а также нормализация прежних ссылок с `@<version>` на актуальную версию без лишнего шага истории. В интерфейсе не должно быть выбора версий, кнопок контекста и мастера добавления. Отдельно нужно убедиться, что nonce меняется между запросами, совпадает в HTML и CSP, а контролы не вызывают CSP-ошибок. Успешная сборка не заменяет эти проверки. Chromium-прогон не подтверждает работу Safari/WebKit.

Для `Visual → Diamonds Collection` есть отдельный `tests/browser-diamonds.mjs`. Он проверяет все десять самостоятельных HTML, совпадение SHA-256 скачиваемого файла с превью, автоматический запуск round-обложки и видимых карточек, реальный WebGL и вращение мышью, отсутствие попапа, освобождение далеких iframe, светлую/темную тему и мобильную ширину. Для проверки lifecycle скрытой вкладки используется синтетическое событие только в одноразовом QA-контексте. HTTP sandbox и `connect-src 'none'` не ослабляются. Этот прогон требует работающий WebGL; отсутствие графического контекста не считается успешной проверкой рендера.

`tests/browser-visual-weblg.mjs` отдельно проверяет исходный renderer опубликованной версии 1.0.0 по ее техническому preview-URL, без зависимости от каталога. Версия 1.0.0 остается неизменной; 1.1.0 хранится рядом. Поэтому API содержит две версии и суммарно 11 записей ассетов, а каталог показывает одну актуальную коллекцию с 10 отдельными огранками. Удаление выбора версий из интерфейса не изменяет исторические raw/preview/API/ZIP-адреса или Git: они нужны для проверки целостности, закрепленных интеграций и отката.

## Откат

Сначала остановить автопубликацию, иначе следующий тик снова установит main. Затем переключить только проверенную ссылку на предыдущий релиз:

```sh
sudo systemctl stop imon-design-library.timer
sudo -u imon-design-library /usr/bin/flock -n /srv/imon-design-library/deploy.lock /opt/imon-runtime/node/bin/node /usr/local/lib/imon-design-library/update.mjs --rollback
curl -fsS https://css.imon.world/health.json
```

После исправления main включить таймер: `sudo systemctl start imon-design-library.timer`. Старые релизы и сборки автоматически не удаляются. Когда библиотека вырастет, нужно добавить отдельную контролируемую политику хранения с сохранением текущего и предыдущего релизов.

## Границы доступа

Код на main считается доверенным кодом владельца. При импорте непроверенных ассетов нельзя добавлять исполняемые шаги в сборщик, workflow или тесты. Пак не может устанавливать npm-зависимости или запускать свой build-скрипт. HTML-превью не запускается во время сборки.

Статус draft и отсутствие в каталоге не делают коммит приватным. Для закрытых клиентских библиотек нужен отдельный приватный репозиторий и авторизация сайта. В текущем публичном проекте такие материалы запрещены.
