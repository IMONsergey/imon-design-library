# Изоляция паков

Библиотека должна собирать несовместимые дизайн-системы без попытки превратить их в один общий стиль. Изоляция здесь решает две задачи: предсказуемое повторное использование и ограничение возможностей превью.

## Четыре границы

| Граница | Механизм | Чего она не обещает |
| --- | --- | --- |
| Файлы | Каждый пак и версия находятся в собственном каталоге; явный список файлов | Приватности публичного GitHub |
| Сборка | Проверка путей, ссылок, манифеста и разрешения публикации; без выполнения кода паков | Полного аудита произвольного кода |
| Превью | Отдельный iframe с sandbox плюс ограничивающие HTTP-заголовки для прямого URL | Безопасности кода после переноса в чужой проект |
| Версии | Адрес содержит id и конкретную версию; опубликованные файлы не изменяются | Автоматической совместимости разных систем |

## Файлы и зависимости

Пак автономен. Его CSS, шрифты, изображения, примеры и правила хранятся вместе. Пути манифеста относительны корню пака; абсолютные пути, обход через `..`, скрытые файлы и символические ссылки не принимаются.

Ссылка `../tokens.css` из `preview/index.html` допустима только тогда, когда после нормализации она остается внутри того же пака и указывает на явно перечисленный файл. Она не может выйти в другую версию или соседний пак.

Сборщик не устанавливает зависимости паков и не запускает их скрипты. Только доверенный интерфейс каталога использует закрепленные зависимости из корневого package-lock.json; они устанавливаются через `npm ci --ignore-scripts --include=dev --include=optional`, без lifecycle-скриптов. Файлы паков не попадают в frontend bundle. Экспортируется только разрешенный список файлов. Нет fallback-раздачи всего репозитория из корня сайта.

## Каталог и фреймы

Главный документ каталога читает только проверенный индекс. Названия, описания и код показываются как текст, не как HTML. CSS и JavaScript ассетов не импортируются в главный документ.

Динамические style-элементы интерфейса требуют свежий nonce запроса. Исключение составляют только два точных CSS-правила скрытия полос прокрутки из закрепленных Radix Select/ScrollArea: они разрешены по SHA-256, а их текст и версии проверяются тестом. Общего разрешения inline style-элементов в каталоге нет. Эти разрешения не переносятся на превью или raw-файлы.

Обычный пак открывается в iframe с пустым sandbox. Если для проверенного превью нужен JavaScript, допускается только `allow-scripts`; `allow-same-origin` не добавляется. Формы, всплывающие окна, доступ к верхнему окну и другие возможности не включаются.

Прямые URL превью должны получать HTTP CSP с sandbox и ограничениями источников. Одного атрибута у iframe недостаточно: посетитель может открыть HTML отдельно. Файлы для чтения `/raw/` должны отдаваться как текст или вложение, не запускаться как страницы.

Новые возможности браузера не включаются в превью автоматически. Запросы на камеру, микрофон, геолокацию, платежи, внешние сетевые обращения или авторизацию означают, что материал нельзя публиковать как обычный пассивный пак.

## CSS-префиксы

Гипотетические примеры префиксов для разных паков. Эти имена не означают, что соответствующие паки есть в каталоге:

- `.example-controls` и `--example-controls-*`;
- `.example-motion`, `--example-motion-*` и keyframes `example-motion-*`;
- `.example-layout` и `--example-layout-*`.

Это удобная инженерная договоренность, но не защита от вредоносного кода. Реальная граница отображения создается отдельным документом и sandbox. Даже аккуратно префиксованный пак не должен напрямую управлять DOM каталога.

При добавлении чужой системы не обязательно переименовывать каждую переменную без понимания ее устройства. Можно сохранить оригинал внутри отдельного пака, описать глобальные селекторы и предложить безопасную адаптацию новой версией.

## Публичность не равна изоляции

Все публичные файлы можно прочитать по их адресам. Разделение паков не скрывает их друг от друга и не является разграничением доступа.

`visibility: "private"` и `status: "draft"` исключают версию из собранного каталога, но не из публичного репозитория. Для клиентских материалов, лицензированных шрифтов и закрытых систем нужен отдельный приватный источник с отдельной моделью доступа. Нельзя коммитить секрет, а затем рассчитывать, что его скроет интерфейс.

## После скачивания

ZIP является набором файлов, не исполняемым установщиком. Владелец проекта сам выбирает, что подключать. Копирование CSS и JavaScript в основной документ другого сайта убирает защиту iframe, поэтому перед интеграцией нужно повторно проверить:

- глобальные стили и reset;
- имена переменных, keyframes и событий;
- внешние запросы, зависимости и обработчики;
- доступность, производительность и reduced motion;
- условия лицензии и атрибуцию.

Sandbox уменьшает возможности кода, но не гарантирует защиту от любой нагрузки на процессор или любого браузерного дефекта. Поэтому первая линия защиты остается простой: сначала осмотр, затем ограниченное превью; JavaScript по умолчанию выключен.
