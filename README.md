# I’MON Design Library

Библиотека веб-ассетов, компонентов, дизайн-систем, правил и артефактов. Каталог для просмотра и выбора; репозиторий для хранения, проверки и версионирования.

Основной адрес: **https://css.imon.world**. Состояние публикации и порядок развертывания описаны в [docs/DEPLOYMENT.md](docs/DEPLOYMENT.md).

## Как устроена библиотека

Один пак представляет одну самостоятельную систему или набор. У него свои файлы, версия, лицензия, источники, превью и инструкции. Стили и JavaScript паков не подключаются к интерфейсу каталога.

Структура каталога: папка → коллекция → отдельный ассет. Коллекция остается версионируемым паком, а папка служит навигацией и не смешивает исходники. Коллекции и ассеты открываются обычными страницами внутри каталога, без попапа просмотра. Можно искать, фильтровать, сохранять коллекции в избранное, читать код, копировать контекст для чата и скачивать отдельный ассет или ZIP коллекции. Есть плитка и список, светлая, темная и системная тема. Избранное, вид и тема хранятся только в текущем браузере, без аккаунта и синхронизации.

Первый раздел: **Visual → Diamonds Collection**. Версия `visual-weblg/1.1.0` содержит 10 самостоятельных HTML-ассетов, по одному на огранку. Обложка коллекции показывает первый, круглый бриллиант. Проверенные превью запускаются автоматически в видимой области; у каждой огранки свой изолированный документ и свой файл для скачивания. Предыдущий исходник `1.0.0` сохранен без изменений, но не дублирует последнюю коллекцию в каталоге.

Интерфейс построен на React и Radix Themes; правила его оформления описаны в [docs/DESIGN_SYSTEM.md](docs/DESIGN_SYSTEM.md). На сервере остается статический сайт: он не принимает загрузки и не выполняет код из добавляемых материалов. Кнопка «Добавить» открывает инструкцию для работы через чат, не форму загрузки.

Пустой каталог является нормальным рабочим состоянием. Библиотека наполняется только материалами, которые владелец прямо попросил добавить или разработать. Настройка проекта и оформление интерфейса не дают разрешения создавать стартовые паки, демо, выдуманные ассеты или фиктивные карточки для заполнения экрана.

## Работа через чат

Укажите материал и куда его положить. Ниже гипотетические примеры запросов, не список существующих паков:

> Добавь прикрепленные кнопки в новый отдельный пак quiet-controls. Разбери состояния, приведи CSS к собственному префиксу, сделай превью и инструкцию. Не смешивай с другими системами.

> Возьми только редакционную сетку из указанного мной пака и версии. Цвета и типографику оставь из текущего проекта.

> Добавь прикрепленный вариант в выбранный мной пак новой версией. Старую версию не меняй. Проверь клавиатуру и reduced motion.

Чат должен читать [AGENTS.md](AGENTS.md), [правила добавления](docs/ADDING_ASSETS.md) и манифест выбранного пака. Название, похожий внешний вид или общие теги не являются разрешением объединять разные системы.

## Локальный запуск

Нужен Node.js 24 или новее. Движок паков остается без сторонних зависимостей. Для сборки интерфейса нужны зафиксированные в корневом `package-lock.json` React, Radix Themes, Inter и esbuild. Устанавливайте только зависимости корня проекта, без lifecycle-скриптов:

```sh
npm ci --ignore-scripts --include=dev --include=optional --no-audit --fund=false
npm run validate
npm test
npm run build
npm run dev
```

`npm run build` сначала собирает интерфейс через esbuild в `.cache/ui/`, затем создает статический `dist/` вместе с опубликованными паками. `npm run build:ui` обновляет только промежуточный интерфейс. Локальный сервер не имеет hot reload: после правок нужна повторная полная сборка.

Локальный адрес по умолчанию: `http://127.0.0.1:4173`. `PORT` и `HOST` можно переопределить переменными окружения. Используйте штатный сервер: он задает защитные HTTP-заголовки и отдельный nonce для стилей каталога. Открытие `dist/index.html` как файла или произвольный static server не заменяет этот режим.

Пример создания черновика под конкретный запрос владельца; `quiet-controls` здесь условное имя:

```sh
npm run pack:new -- quiet-controls --version 0.1.0 --title "Quiet controls" --category components
```

Команда создает техническую основу, но не дает разрешение на публикацию и не заменяет запрошенный материал. Не публикуйте ее шаблон как готовый ассет. Источник, права, реальные файлы и проверку нужно заполнить отдельно. Синтаксис: `node scripts/new-pack.mjs --help`.

## Структура

| Путь | Назначение |
| --- | --- |
| `packs/<id>/<version>/` | Изолированная версия пака, ее manifest.json и файлы |
| `frontend/` | React-интерфейс и собственные стили каталога |
| `site/` | HTML-оболочка, favicon и ранняя установка темы |
| `.cache/ui/` | Промежуточный скомпилированный интерфейс, не хранится в Git |
| `scripts/` | Проверка, создание пака, сборка и локальный сервер |
| `schemas/` | Машинно-читаемые схемы |
| `tests/` | Автоматические проверки |
| `docs/` | Контракт, правила работы, изоляция и развертывание |
| `inbox/` | Локальная карантинная папка, исключенная из Git и публикации |
| `dist/` | Результат сборки, не хранится в Git |

Сборка генерирует `/api/catalog.json`, манифесты конкретных версий, файлы для чтения, изолированные превью и ZIP-архивы. Каждому экспортируемому файлу соответствует размер и SHA-256. Формат описан в [docs/CONTRACT.md](docs/CONTRACT.md).

Шрифты и зависимости интерфейса отдаются с собственного домена, без внешнего CDN. Файлы паков не входят в frontend bundle. Нельзя выполнять `npm install` внутри пака или подключать его стили к оболочке каталога.

## Публикация и версии

В сайт попадают только паки с `status: "published"`, `visibility: "public"`, указанной лицензией и подтверждением публикации. Копируются только явно перечисленные файлы. Проверки не запускают код пака.

Опубликованная версия неизменяема. Исправление CSS, документации или файла оформляется новой версией. Это позволяет проекту использовать конкретную версию, не получая неожиданные изменения вслед за каталогом.

4 ноября 2026 владелец отдельно разрешил удалить из текущего дерева и каталога три демопака версии `1.0.0`: `interface-foundation`, `motion-essentials` и `layout-recipes`. Их прежние файлы сохранены в истории Git. Это разовое разрешение на удаление конкретных паков, не общее право менять опубликованные версии или возвращать демо без нового запроса.

Публикация на сервере должна проходить через проверку и сборку, а затем атомарное переключение релиза с возможностью отката. Точные команды и фактическая конфигурация: [docs/DEPLOYMENT.md](docs/DEPLOYMENT.md).

## Публичность и права

**Этот репозиторий публичный.** `draft` и `visibility: "private"` управляют сборкой, но не скрывают файлы в GitHub. Для закрытых материалов нужен отдельный приватный источник. Не коммитьте клиентские секреты, токены, пароли, платные шрифты без права распространения и чужие ассеты без понятной лицензии.

`inbox/` не является резервным хранилищем. Если материал нельзя потерять, сохраните оригинал в согласованном приватном месте до обработки. Не переносите его в публичный Git ради резервной копии.

Код проекта и добавляемые материалы не получают открытую лицензию автоматически. У каждого пака своя лицензия в файле, указанном в `license.file`. `license.redistribution: true` означает, что его публикация в этом каталоге разрешена; это не заменяет условия лицензии и не дает посетителю безусловного права использования.

Сторонние библиотеки и шрифты интерфейса сохраняют свои лицензии. Их уведомления собираются в `/third-party-notices.txt`; лицензия проекта их не заменяет.

## Границы первой версии

Загрузка через сайт, учетные записи, платные/закрытые разделы и автоматическая обработка произвольных архивов не реализованы. Добавление идет через файлы и Git, а просмотр через безопасный статический каталог. Направления развития: [docs/ROADMAP.md](docs/ROADMAP.md).
